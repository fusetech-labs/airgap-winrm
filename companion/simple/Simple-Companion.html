SIMPLE COMPANION

Sysadmin Download Toolkit 1.1, for a PC where PowerShell is restricted or blocked - the versions this site has deployed, where the next ones are published, and a check of every file fetched by hand

What this page is for

  • The Download Toolkit is a PowerShell tool, and some PCs do not let it run: application control (AppLocker, WDAC and similar) holds PowerShell in ConstrainedLanguage mode, or scripts are blocked altogether.
  • This page is the simple companion for such a PC. It needs a browser and nothing else: nothing is installed, no script runs outside the page.
  • It does the part a person can do by hand, and keeps it straight: what is deployed, where the next version is published, whether the downloaded file is the right one and is intact. Finding and fetching every update by itself, on a schedule, stays with the Download Toolkit on a PC where it runs.

The versions file

  • A plain text file, one product a line. The Settings tab adds and removes the lines; the Versions tab fills in the versions; Notepad reads and writes the same file.
  • Lines that start with # are notes and stay as they are. A note may follow a version after #.
  • Software of the site's own may carry the page it is published on and its release notes, each between < and >.
# what this site runs today
Windows Server 2022 cumulative update = KB5136487   # installed 2026-11-14
Windows Server 2022 .NET Framework 4.8.1 cumulative update = KB5127693
PuTTY = 0.83
Our own agent = 7.2.1 <https://downloads.example.com/agent/> <https://downloads.example.com/agent/notes>

Open and Save

  • Microsoft Edge and Google Chrome: Open versions file reads the file, and Save writes it back in place after the browser has asked once. The page remembers the file: the next time, Open versions file opens the same one, and the file dialog starts in its folder.
  • A browser does not let a page choose the folder its file dialog starts in. The first time, find the file beside this page - or drag it from its folder onto the page, which opens it without any dialog.
  • Other browsers: Save hands the file over as a download. Put it in place of the old one.
  • The page starts with a choice. Open versions file carries on with the file there is. Start a new list gives the list the Download Toolkit starts with: set what this site runs on the Settings tab, fill in the versions, Save. A new list saved under the name of an existing file replaces that file.

Settings

  • Windows Server: a tick adds the rows of that version - its cumulative update, its .NET Framework updates, the servicing stack for Server 2016 - and taking the tick away removes them.
  • .NET Framework: the versions in use on the servers. A server version has a row for each ticked .NET version that exists for it: 4.8 for Server 2016, 4.7.2 and 4.8 for Server 2019, 4.8 and 4.8.1 for Server 2022, 4.8.1 for Server 2025.
  • SQL Server: a row for each version in use, and Management Studio. The Update Catalog lists a version's Cumulative Updates and its Security Updates together: take the Cumulative Update, or the Security Update of the branch the servers are on - CU where a cumulative update has been installed, GDR where only security updates have.
  • Software: the products the page knows. Software of this site: anything else, with the page it is published on and its release notes if it has them.
  • A row that holds a version or a note is removed only after a Yes. Nothing reaches the file before Save.

Looking for a newer version

  • The links open the place each product is published: the Microsoft Update Catalog searched for the product, Microsoft's list of every release, the vendor's download page, the release notes.
  • The Update Catalog lists every release of the product, the newest first: the top rows are the ones to compare. A month may hold two cumulative updates, the monthly one and a later one that includes it - take the later; leave a row that says Preview or Dynamic Update.
  • .NET Framework: a month holds a row for each .NET version and one that names two versions (3.5, 4.8 and 4.8.1). Take the row that names only the version of the row on this page, with or without 3.5; the row that names two holds the files of both. Not every month has a .NET Framework update.
  • Latest at the source is the newest version the source has. Check sources reads it where the vendor lets a page read its list: WinSCP, Wireshark, Notepad++, OpenSSH, Firefox ESR. The Update Catalog, Microsoft Edge, PuTTY, VMware Tools and the others do not let a page read them: open the link and type what it shows.
  • The Status column compares it with the Deployed column: Up to date, or Update when the source has a newer one. Download with the browser.
  • The page reads from the internet only after Check sources or Read from the source, and only those vendors' own lists.

Checking a downloaded file

  • Check a file (or drop the file on its row) reads the version of the file and compares it with the Deployed column: Deployed, Newer, Older or Different. The version comes from the file name, and from inside the file as its Properties show it (In the file): the ProductVersion of an .msi - for Microsoft Edge and Google Chrome the version in its Comments - and the Product version of an .exe. Where the name carries no version, the one inside is taken; where the two differ, Use takes the one inside. An update (.msu) carries its KB in its name.
  • The SHA256 and SHA1 of the file are worked out in the browser, and compared with what the source says. An Update Catalog file carries the catalogue's SHA1 in its name: the page compares the two by itself (Catalogue SHA1).
  • Published SHA256, for the other files: Read from the source asks the vendor's own list where a page may read it (WinSCP, Wireshark, Notepad++, OpenSSH). Published hashes opens the vendor's list for the rest.
  • A vendor's list holds many hashes, and the page does the searching: on the list press Ctrl+A and Ctrl+C, then Search the copied list here (the browser asks once whether the page may see what was copied). Or paste the list into the box, or drop the list's file on the box or on the row. The page looks for the SHA256 of the checked file in it and says what the list names beside it: the file, and its version where the list gives one (Microsoft Edge). A hash that differs, or a list without it: Mismatch.
  • A .NET Framework file names its .NET version (ndp48, ndp481, ndp472), a SQL Server file its SQL Server version. On the row of another version, or a .NET file on a Windows row, it is a Wrong file.
  • The signature cannot be read in a browser. Open the file's Properties, Digital Signatures: the signer must be the one the row names.
  • Set as deployed, after the version is installed everywhere, writes the file's version into the Deployed column. Save keeps it.
  • Save CHECKSUMS.txt writes the SHA256 and name of every file checked, to carry across with the files.
